# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

A Meta Quest VR target-shooting game built with **Unity 6000.3.14f1** (URP 17.3). Players fire bullets from both controllers at moving targets within a 60-second time limit. Targets use the Meta XR SDK (`com.meta.xr.sdk.core` / `interaction.ovr` 201.0.0) on top of OpenXR, and the build target is Android (Quest).

## Building and running

There is no CLI build script, test suite, or linter. Everything goes through the Unity Editor:
- Open the project in Unity 6000.3.14f1 and use **File > Build Profiles** (Android) to build and deploy to a Quest. Previous builds were output as `a.apk` in the repo root.
- Scenes in the build, in order: `StartScene` (index 0 among enabled ones), then `GameScene`. `SampleScene` is disabled.
- `com.unity.test-framework` is installed, but there are no tests yet.
- `Assembly-CSharp*.csproj` and `TestShooting.sln` are generated by Unity; do not edit them by hand.

Ignore generated or editor-owned folders: `Library/`, `Logs/`, `obj/`, `.utmp/`, `.vs/`, `UserSettings/`, `*_BurstDebugInformation_DoNotShip/`, `*_BackUpThisFolder_ButDontShipItWithYourGame/`, and `Assets/_Recovery/` (auto-recovered scene backups).

## Architecture

All game code is in `Assets/Scripts/` (default `Assembly-CSharp`, no asmdefs).

**Scene flow:** `StartScene` contains a blinking `StartTarget`. Shooting it (a collision with an object tagged `Bullet`) loads `GameScene` by name. In `GameScene`, `GameManager` runs the timer. On time-out, it disables `TargetSpawner`, destroys every object tagged `Target`, shows the result panel, and returns to `StartScene` after 15 seconds. Scene names are hard-coded strings in `SceneManager.LoadScene` calls.

**GameManager** is a scene-local singleton (`GameManager.Instance`, not `DontDestroyOnLoad`). It owns score, timer, UI (TMP texts, result panel), BGM, and all SFX. Other scripts call `GameManager.Instance.PlayShootSE()/PlayHitSE()/PlayDestroySE()/AddScore()`, so these scripts assume a `GameManager` exists in the scene.

**Shooting:** `BulletShooter` polls `OVRInput` (`PrimaryIndexTrigger` → left fire point, `SecondaryIndexTrigger` → right fire point). It instantiates `Bullet.prefab` and sets `Rigidbody.linearVelocity`. `Bullet.OnCollisionEnter` calls `Target.Hit()` on whatever it hits, then destroys itself (it is also destroyed automatically after 20 s).

**Targets:** `Target` is the base class (HP, score, hit SFX, white-flash `DieCoroutine` before `Destroy`). `YellowTarget` (1 HP, 1 pt), `RedTarget` (3 HP, 3 pt), and `GreenTarget` (1 HP, 0 pt) subclasses set `maxHp`/`scoreValue` in `Start()` before calling `base.Start()`. This overrides any Inspector values. Each target has a prefab in `Assets/Prefabs/`. `TargetMovement` (a separate component on the prefabs) chooses one random pattern (Horizontal/Vertical/Circle/Lissajous) from its serialized list and oscillates around the spawn position.

**Spawning:** `TargetSpawner` spawns every `spawnInterval` seconds, up to `maxTargetCount` live `Target`s. It picks a prefab by weighted probability (yellow/red/green rates) and places it on an arc in front of the `player` transform (distance and angle range, at the player's height).

**Tags** `Target` and `Bullet` are defined in `ProjectSettings/TagManager.asset`, and gameplay logic depends on them.

`DebugUI` is a simple singleton for showing a message on an in-headset TMP text.

## Conventions

- Existing `.cs` files are **Shift-JIS (CP932) encoded with CRLF**, and their comments are in Japanese. Keep this encoding when editing, or the Japanese comments will be corrupted. Convert explicitly only if the user asks.
- Code style: Allman braces; long expressions are wrapped across multiple lines (e.g. `rb.linearVelocity =\n    firePoint.forward * bulletSpeed;`); `[SerializeField] private` fields are preferred for Inspector wiring.
- Use the Unity 6 APIs that are already in use: `Rigidbody.linearVelocity` (not `velocity`) and `FindObjectsByType` (not `FindObjectsOfType`).
- When you add or rename serialized fields, the references must be re-wired in the scenes/prefabs in the Editor. Mention this to the user, because the YAML scene files should not be hand-edited.
